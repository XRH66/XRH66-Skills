# 项目文件库

以清楚的索引和唯一的权威正文组织项目。保留六类核心职责，复用已有入口；目录根据当前项目决定。

精简须保留三个条件：索引准确、状态明确、交接可恢复。

优先更新已有内容及索引。只有内容无处归属，或确需独立查找、编辑时才新建文档或分区；不预建空目录、空记录或无用栏目。整理的目标是减少查找和维护成本。

## 当前工作方式与完成标准

按用户要求选择工作方式，可在授权范围内组合；只读时不写入，保存方案仅写规划文档。

| 工作方式 | 完成标准 |
| --- | --- |
| 技能制作或评审 | 交付本次草稿修订或审查结论，检查格式与引用；不执行建库或安装 |
| 讨论、只读检查 | 回答问题并说明未明确事项，不产生项目记录 |
| 规划 | 给出符合规划参考的方案，区分现有与拟建内容，不要求落地 |
| 建库 | 本次授权的六类入口可读取，内容、索引与实际成果一致 |
| 维护 | 受影响内容及必要引用一致，不重建全库 |
| 恢复或接续 | 说明当前目标、实际进展、遗留问题及恢复点；实际接管后按职责参考更新交接标记 |

建库授权只涵盖文件库工作。业务创作、开发、软件安装、资产修改和发布按用户实际任务执行；历史记录只恢复上下文，不自动恢复旧任务授权。

## 识别项目与规划

1. 确认工作位置和适用规则。已指定的项目目录直接使用，不嵌套同名目录；位置不明时澄清。
2. 定向读取已有入口及相关文件，识别目标、交付物、阶段与缺口，保留用户有效内容和工具固定结构。
3. 首次规划、调整结构或补充项目信息时，读取 [提问与规划要求](references/Planning.md)，只补问实际缺口，将六类职责映射到适合当前项目的入口。

## 建立与维护文件库

规划核心职责、维护文件库或恢复上下文时，读取 [六类职责与维护规则](references/SixFiles.md)。职责、命名、索引与交接判定以该参考为准。

写入时先保存实际成果和必要证据，再更新相关记录、当前信息及索引；只维护受影响内容，使用项目约定语言和 UTF-8。

实际入口和维护约定保存在项目自身的索引或规则中，使后续 agent 无需安装本 skill 也能接续。

冲突时用当前用户要求确定目标，用实际成果与证据确定进度，不以编辑时间代替核实。

## 恢复工作

从适用工作规则进入总索引、项目说明和当前状态，再按任务读取记录与有效交接；不循环重读或机械选择最新交接。

入口缺失时，在已授权位置查找已有说明与状态，说明可用入口及缺项；不要求先建库，也不虚构入口。

核对实际文件、适用条件和未完成操作，按当前授权接续；条件未变化的验证沿用原依据。只读恢复不改交接标记。

## 中断与部分完成

核对已产生的结果，说明完成项、缺项、原因与恢复点；仍可写入时保存记录和状态，有正式交接需要时才写快照。不能保存的信息在回复中说明。恢复时只补缺口，保留已完成结果。

## 按本次范围核对与交付

按工作方式表收尾，检查受影响的内容、任务关系及链接；建库另查六类入口可达性。简要报告成果、检查结果及未核实项，不扩大为全库检查。结构检查不替代业务验收或独立接续验证，局部完成不等于项目完成。
