# 六类职责与维护规则

总索引、项目说明、工作规则和项目状态以文件为基础，工作记录和交接用文件夹承载多次记录。以下为缺省名称，已有项目复用等效入口。

工作范围见 [SKILL.md](../SKILL.md)，规划方法见 [Planning.md](Planning.md)。

## 1. 总索引：Index.md

维护六类职责、实际内容区域和权威正文的入口，指向具体文件或任务章节，简述用途与阅读路线；涉及多版本或交接时标明当前有效项。正文留在各自位置，入口或归属改变时更新索引。

## 2. 项目说明：ProjectContext.md

维护当前目标、使用场景、交付物、完成判定、范围与业务约束；已确认事实、建议和待明确项分开表达。操作约定归工作规则，共同涉及的要求确定一个权威位置，另一处引用。

项目要求随工作发展更新，注明来源、适用范围、确认或验证时点及重验条件。有依据的事实变化和用户明确的新要求直接纳入；改变目标、缩小范围或放宽要求的取舍由用户决定，日常实施判断由 agent 处理。

变更时更新现行正文，工作记录保留依据与影响，并按实际影响更新状态和交接适用性；建议不自动成为已确认要求。

## 3. 工作规则：AGENTS.md

维护项目入口及必要的文件保护、命名、编码、工具操作和记录约定；详细规则引用原文，临时任务留在状态或记录中。操作方式改变时更新。

Codex 复用已有 AGENTS.md，读取后局部增补，保留有效指令，不自动修改全局配置。其他 agent 使用实际支持的规则入口，并确保入口可发现；不能假定文件存在就会自动读取。冲突按当前明确要求及适用范围处理，不静默覆盖。

## 4. 项目状态：ProjectStatus.md

精简维护当前工作快照：

- 核实时间与对象；编辑文案不刷新核实时间。
- 当前任务的已完成、未完成和未核实内容，以及可用成果、阻塞与待决定项。
- 下一步的对象、动作与可观察结果。
- 相关成果、记录、证据和有效交接的入口。

按任务组织，必要时注明负责范围；详细问题引用正文。实际进度、验证有效性或下一步变化时更新。

## 任务关联、结束与并行维护

状态、记录和交接用已有编号或清楚名称对应任务，不强制另建编号体系；相近主题及替代关系注明对象与范围。

任务完成、取消或被替代时，在已有最终报告或结项工作记录保存结论、成果、验证、遗留问题与结束原因，适用时链接替代任务。记录索引保留结束标记和最终入口；当前状态移出该任务前，保留被引用的简短结束说明或修正引用。同步交接适用性，没有下一步就写无。

并行 agent 使用独立记录，局部更新各自任务。共享状态和索引写前读取、写后核对；发现内容变化或写入竞争时先合并或协调，未消解前停止覆盖该位置，不用旧全文覆盖新内容。

## 记录目录与命名

记录目录示例：

```text
WorkLogs/
  Index.md
  WorkLog202610171420方案调整.md

Handoffs/
  Index.md
  Handoff202610171645.md
```

- 工作记录名为 WorkLogYYYYMMDDHHmm任务简名.md；交接名为 HandoffYYYYMMDDHHmm.md，必要时可接主题。
- 年月日时分直接连写，不加连字符或冒号；年份四位，其余各两位，使用 24 小时制。
- 任务简名或交接主题使用简短文字，去除路径分隔符及文件系统不允许的字符；完整任务名称保留在正文。
- 文件名采用创建时间，正文注明创建时间和项目统一时区；补充内容另记更新时间，文件名不变。
- 同一分钟多份记录以任务简名或清楚序号区分；创建前核对重名，创建时采用不覆盖已有文件的方式，遇重名改用新的简名或序号。

## 5. 工作记录：WorkLogs 文件夹

每个有意义的工作单元保存一份记录：创建时间与时区、任务与当时范围、实际变动及原因、成果位置、检查结果和遗留问题。正文已有的细节直接引用。进行期间补充同份并记更新时间，收尾后保留；后续工作另记并关联前文。

记录随实际收尾、阶段成果或中断检查点产生，不记逐条工具调用或普通只读问答。初始化只记录本次真实工作，不虚构历史。已有单个旧日志或交接文件时保留原件，由记录索引引用，后续使用文件夹。

## 6. 交接：Handoffs 文件夹

用户要求、更换 agent，或中断且有接续现场时新增交接快照；普通收尾只更新记录与状态。快照保留形成时的现场，只写接续所需信息，已有详细结果引用工作记录。

每份正式交接快照至少包含：

- 所属任务、形成时间和时区。
- 工作位置、首个阅读入口和必读文件的理由。
- 实际停靠点、未完成或未核实内容；部分执行的操作写明已有结果与缺项。
- 工作记录、成果与依据的位置，缺失内容如实注明。
- 下一步具体动作及继续前必须核对的条件；没有下一步时明确写无。

影响接续的版本、临时进程、未保存内容或并行修改按需补充。

交接索引维护当前适用性及其变化时间、依据：

- **待接续**：尚无可核实的接管记录。
- **已接续**：接手者核对现场，将续作信息落实到状态或新记录；索引链接接管位置，说明核对、已做及尚未做的内容。仅读取不算接管，接管不等于任务完成。
- **已失效**：现场取消、结束、变化或被明确范围的新交接替代，注明依据与当前入口。

各任务独立判定，不以全局最新时间替代其他任务的交接。没有待接续现场时，索引注明并链接状态，不创建空快照。

## 历史与证据引用

历史保留当时事实与建议，后来结果另记；更正注明日期、原因与依据，可补导航但不改写历史进度。当时建议与当前下一步有别，当前以项目状态为准。

验证注明对象版本、范围与时点，保留当时证据，优先引用已有报告、提交或原生版本记录；少量证据可直接写入，不复制整套资产。可覆盖的最新文件或动态状态不能证明旧结论，原证据丢失须注明。条件不变沿用依据，变化后只重验受影响部分。

## 关联索引与横向引用

总索引管入口，正文管内容，当前状态管进度，记录管历史。详细事实只维护一份，其他地方以短说明和链接引用。

- 总索引连接六类入口及实际内容区域；只有内容较多、确需独立导航时再设分区索引。
- 两个记录索引列出时间、任务与记录链接；工作记录索引保留任务结束入口，交接索引另维护适用性及依据。新增记录同步所属索引和受影响的任务入口。
- 状态按任务连接成果、依据、记录和有效交接；记录链接所属索引与任务入口。来源、产物、验证、前后序及替代关系按实际需要横向引用，说明关联原因。
- 每份可维护文档有归属或返回路径；可通过共同索引往返，不要求每对文档都建立双向链接。原件、二进制及工具原生文件由外层索引关联，不修改原件来加链接。

库内文件使用可解析的相对链接，必要时指向明确章节。库外来源保留原始 URL、原生文档标识或明确位置；依赖特定设备或权限时注明访问条件，不为改成相对链接移动或复制原件。

位置改变时修正受影响的引用，受保护历史资料由外层索引说明位置关系；只检查本次受影响的路径及任务。

## 按需整理

出现重复、过期当前信息或查找困难时，收敛重复正文，保留独有有效内容并修正索引。已结束内容从活跃入口转为历史入口，无需为归档另建一套报告或目录；原始资料和历史记录保留，移动或删除按当前授权处理。
