# 提问与规划要求

首次规划或调整结构时使用。范围见 [SKILL.md](../SKILL.md)，维护约定见 [SixFiles.md](SixFiles.md)。

## 按信息缺口提问

先读当前要求与已有资料，只问会影响规划且无法查明的缺口。以下问法按需选用，优先明确目标、交付物和起点；目录设计由 agent 提出。

| 需要了解的信息 | 面向用户的问法 |
| --- | --- |
| 项目目标与完成判定 | 这个项目主要要解决什么问题？做到什么程度，你会认为它完成了？ |
| 最终交付物 | 最后需要交付哪些东西？例如可编辑工程、导出成品、研究报告或操作说明。 |
| 当前起点 | 目前已经有哪些资料、工程或成果？哪些是当前有效版本，哪些只是参考或历史内容？ |
| 实际工作过程与阶段 | 接下来大致会开展哪些工作？目前准备先做哪一步？ |
| 当前已确认的约束 | 目前已经确认有哪些必须遵守的要求或限制？哪些还需要研究、验证或后续决定？例如需要原样保留的内容、已有约定或工具固定路径。 |
| 使用与协作方式 | 平时主要怎样查找和使用这些文件？是否会有多人或多个 agent 同时工作？ |

用户不确定时先给建议，区分已确认内容与待明确事项。不影响当前规划的未知项保留；会实质改变结构的先澄清。后续只补问变化部分。

## 规划应交付的内容

交付一份与项目规模相称的短方案，包含：

1. **项目理解**：目标、交付物、阶段与约束，区分事实、建议和未知项。
2. **结构与归属**：六类职责的入口，以及实际输入、工作文件、成果和历史的存放位置；注明用途与权威正文。标明已有、拟建及按需建立的位置，拟建路径不写成有效链接。每个新增区域须有当前用途，不照搬其他项目目录。
3. **索引与接续**：从哪里进入、按任务读什么、变化时更新哪里。仅在项目规则入口保存接续必需的维护约定，不另建重复规则文档。
4. **现有内容与分歧**：保留和补充什么；确需移动、拆分或改名时列明对象、理由、影响及引用修正。只把需要用户决定的重要分歧留待确认。

检查方案能否让人找到当前内容、分清权威版本，并让新 agent 定位状态、依据和恢复点。能通过已有正文与索引解决的问题，不另建说明或检查报告。规划通过不代表已经建库或完成业务验收。
