# 参考图驱动的程序化建模

## 这份 skill 管什么、不管什么

**管**：判断顺序、每阶段的做法与过关判据、什么症状回到哪一步、背后的数学原理、可复用的领域无关原语、证据怎么留。
**对象范围**：以硬表面为主；附在硬件上的软件（皮带、衬布、垫层）做到 L2 跟形，小五金（带扣、铆钉、环）按规则件做（`geometry-math.md` §7b）。
**不管**：某个具体物体的几何代码怎么写。那是执行模型的能力——按本 skill 的原理（`references/geometry-math.md`、`math-form.md`）和原语（`references/code-index.md`）现写，写在项目目录里。案例代码只作参考，不搬进 skill；项目里反复出现的通用逻辑才抽成原语（§8）。

出错几乎都出在**顺序颠倒**：拿细节弥补大形不准，在读错的线上拟合得很准，或者在错的造型上反复修补审计。

## 六条总原则

1. **扬长避短，分级逼近**：长处是规律（制式、重复、对称、排布、装配、少参数曲线），短处是自由雕塑面。不规则件一律先做到剪影体，再挖能规则化的子结构（`references/levels.md`）。
2. **数形结合，互相修正**：结构（几层、几件、谁压谁、截面是什么）来自识别；数据（参考上的线、点、剪影）只调这个结构的少数族参数。拟合残差反过来检验识别——残差大或几种数据互相打架，先回去查是不是认错了，不加参数硬凑（`references/fitting.md`）。
3. **先大后小，一轮一层**：大形（剪影、比例、面型）不过，不进中形（曲线性格），中形不过，不进小形（构件细节、材质）。
4. **一切形都要能说出来源**：每个形状参数要么来自参考读数，要么来自查证的规制 / 先验，要么是审美决定，并写明是哪种。写进单一 spec。
5. **证据三件套**：同机位图 + 数字（IoU / 残差 / 审计）+ 文件（路径 / md5）。给用户看的是图，不是代码和日志。
6. **没覆盖的就查**：规制、真实尺寸、材料物理量、算法、API 差异，联网查一手来源再落地，留出处（`references/research.md`）；不能联网时请用户提供资料，并把结论标成待核。

标记（可信度从高到低）：**[已验证]** 完整项目跑到交付；**[实测]** 真实项目上跑过、有数字；**[自检]** 合成数据自检通过；**[待验证]** 推断。

## 流程与检查点

```
0 开工前 → 1 识别 → 1b 自检 + 粗模 ⇒【检查点 A】→ 2 定级 → 3 拟合 → 4 构造 → 4b 逐件对照 + 同机位对比 ⇒【检查点 B】
       → 5 材质 ⇒【检查点 C】→ 6 验收 → 7 交付 → 8 沉淀          （任何一步出现回退信号 → §10 查表回到对应步）
```

| 步 | 产出（没有就不进下一步） | 闸门 | 细节 |
|---|---|---|---|
| 1 识别 | 参考清点（五类、视图表、歧义）+ 构件树 + 每节点八问 + 初定级 + 参考局部放大图 | `gate.py ident` | §1，`levels.md` |
| 1b 自检 | 逐节点核规则；粗模同视角对比；用户过目 | `gate.py selfcheck` | §1b |
| 2 定级 | 复核每件目标级 L0–L4 / skip、歧义点 | — | §2 |
| 3 拟合 | 每个形参的值 + 来源 + 误差 + 回代图，写进 spec | `gate.py measure` | §3，`fitting.md`、`math-form.md` |
| 4 构造 | 精品件 → 实例 / 对称展开 → 装配，审计过 | — | §4，`geometry-math.md`、`gn-patterns.md` |
| 4b 对照 | 逐件特写 vs 参考局部；同机位对比 + IoU | `gate.py accept` | §4b |
| 5 材质 | 成因分层、三个尺度带 | — | §5，`materials.md` |
| 6–7 | 求值后审计、冷启动、归位、md5 | — | §6–§7 |
| 8 沉淀 | 通用逻辑进 skill，项目只留数据 | — | §8 |

**闸门**（`scripts/gate.py`）只查"做没做、有没有依据"，查不出"做得对不对"。对不对靠粗模对比、逐件对照和用户过目。只有用户明说才能跳步，并在交付物里写 `"skipped": "用户原话"`。
**审计全过 ≠ 像**：审计只管几何干净。交付时先给对比图，再报审计。

**检查点与中断** [实测]：只在 A / B / C 三个检查点停下给用户看；阶段内的自检、闸门、审计、回代自己做，不过就自己改，不每步问"继续吗"。只有真正要用户定的事（方案族选哪个、动用户的东西）才中途问。给用户的是图（对比图、叠图、分件图、单件特写），图上标名字和关键数字。

## 0. 开工前 [已验证]

- **清点工具**：环境里的工具插件（先列目录）→ Blender 已装插件（`addon_utils.modules()`）→ 本 skill 的 `scripts/`（`references/code-index.md`）。用前先跑 selftest。工具的坑见 `references/toolchain.md`。
- **定执行通道**：无头副本还是用户的主 GUI Blender；主 GUI 走"租约 → 执行 → 快照 → 释放"，代码先在无头副本跑通（`references/toolchain.md`"连接与执行通道"）。
- **项目纪律**：
  - 单一数值源：尺寸 / 参数只写在一个 spec 模块，生成脚本 import，不复制数值；
  - 单一生成器：成品由生成脚本从头构建；副本上的补丁只算实验，结论回收进生成器；
  - 命名：对象前缀 = 构件类别，集合与前缀一一对应；
  - 改拓扑前先快照。
- **协作边界**：灯光、世界、合成、视图变换归用户，构建只建几何与材质，临时灯 / 临时关合成渲完恢复；用户 GUI 开着的文件不覆盖；用户说"先分析"就只分析；没跑过的代码先在无头副本里跑通；借项目函数做实验先把输出目录指到草稿目录。

## 1. 识别：分类 → 拆件 → 八问 [已验证]

**做什么**
1. **分类**：参考里每样东西归成主体 / 插图（放大拼图、细节插页）/ 标注 / 干扰物 / **存疑**（参考自身前后不一致、生成图伪影，如莫名的字符、两视图细节对不上）五类，只有主体进入后续；存疑的不建，列进歧义清单请用户定。
2. **视图清点**：一张参考可能有几个视图（正 / 背 / 侧、转角视图、插图）。逐个拆出子图，记朝向、大致转角、有无强透视，标用途 primary（主对位视角，至少一个）/ aux（辅助）/ ignore；视图之间对不上的地方记下来。多视图怎么联合用见 `fitting.md` §2b。仰视时水平件的底面会露出来，可见的边不一定是立面线。
3. **拆件，建构件树**：整体 → 部件 → 件 → 基本单元。依据按优先级：真实构造 > 材质 / 分缝 > 重复 > 对称 > 规律性。
   - **根** = 整件本身（id `root`，role `assembly`）。
   - **parent = 这件坐在 / 装在哪个件上**；同时贴着几样东西时，挂在承力或最先装的那个上，其余写进⑥装配。
   - 每个节点记角色（support 支承 / part 件 / mount 件上的安装件 / detail 小件）、数量、排布规则、**接口**（坐在谁上、朝哪，原点放这里）。
   - **mount 与 detail 的界线**：有自己的体积和接口、能单独拿下来看的（铰座、凸台、带扣、铆钉、徽章）是 mount；长在父件表面、离开父件就不成形的（刻线、小卷纹、缝线、浅浮雕）是 detail，写去向 `route`（独立网格 / 父件上的几何浮雕 / 法线 / 材质 / 外部资产）。板上的铰座、凸台、槽是 mount，挂在它坐的那个件下面，不当成"板的一段"。
4. **支承体也是节点**（role = support，挂在根下）：件坐在什么上（手臂、柱身、屋面壳、器物腹），支承本身的走势、粗细节奏、截面变化也要识别，写明外形来源 `profile_source`（剪影拟合 + 用哪些视图 / 已知形 / 实测；先验只当初值，不算来源）和交不交付 `deliver`（人的手臂通常只作支承不交付）。后面同样从参考拟合，不用线性插值的直管 / 平板代替（`fitting.md` §5）。
5. **出独立几何的 L0–L3 节点答八问**：① 是什么、在哪、接口；② 对称群；③ 重复与变化参数；④ 轮廓能否少参数写出；⑤ 高度结构；⑥ 装配关系；⑦ **面型**（明暗连续渐变 = 曲面；成块、有亮棱暗缝 = 硬表面；抛光金属上一条窄高光带不一定是棱——看它两侧的面明暗是否突变，或换一个视图看它是否跟着走）；⑧ **跟不跟所坐的面**（parent 的面；坐在支承上就是支承形。理由只能是薄 / 软 / 小，刚性件自有截面）与**两向截面**（沿主轴一刀、绕主轴一刀，各是曲线还是折线、几段）。
6. **每个叶节点切一张参考局部放大图**（`ref_trace.py crop`，不能拿原图充数），描述要在图上对得上（说"三个平面"，图上数得出三个面；说"长槽"，图上看得出长宽比）。
7. **每个节点初定级**（L0–L4 / skip），阶段 2 复核；看不清、定不了的结构写进歧义清单 `ambiguities`，能用另一个视图消掉的先消掉，不算歧义。

**过关**：`gate/ident.json` 过闸——参考清点、视图表、歧义清单、树、八问、证据图齐全（字段表见 `levels.md` §1c）。量尺寸靠工具出数字，不靠目测；这一步量到的数字直接写进 `gate/measure.json`（阶段 3 再补全）。
**常见错**：把外露的支承和覆盖在上面的件认混（护臂：肋纹金属壳被当成外露衬袖——金属高光、和甲板同材质是区分信号）；只拆到"一块板"，板上的铰座 / 凸台 / 槽没拆出来。

## 1b. 自检 + 粗模 ⇒ 检查点 A [实测]

1. **逐节点对规则核**（文字层）：拆到底了吗？面型判对了吗？跟形判对了吗？两向截面都定了吗？**做法是从旧案例搬来的吗，搬的理由这里还成立吗？**
2. **放大图对照**（证据层）：描述和放大图逐件对，对不上改描述。
3. **粗模对比**（几何层，最可靠）：L0 / L1 几何（方盒、折线截面、无细节）按参考视角出图，并排 / 叠图看剪影与大块明暗。粗对位只到"位置比例、面型对"（剪影 IoU ≈ 0.8）就停（`fitting.md`）。不开 Blender 也能做：多边形汤 → `preview.py` 平涂 / 掩膜 → `silhouette_iou.py`。
   - 拼图参考先按视图表的 region 原样切出子视图（`ref_trace.py crop --raw`），掩膜和 IoU 都在子视图上做；
   - 这时还没拟相机：正交视图（工程图式的正 / 侧 / 俯）用 `preview.ortho` + 实测像素 / mm 比直接对；透视视图只做目测并排，同机位 IoU 推迟到阶段 3 定了相机之后。
4. **改了树就重过闸**：自检改了构件树或字段，重跑 `gate.py ident`（`gate.py selfcheck` 会先重查 ident）。

**检查点 A**：交给用户——构件树 / 分件图 + 每件面型、截面、跟形结论 + 放大图 + 粗模对比图。用户 ok 后进定级与构造，到 B 之前不再中断。大件或第一次做的类型，可找一个没参与本任务的读者（不带上下文的子代理、新会话，或另一个人）只读参考和 ident.json 冷读挑错，结论写进 `selfcheck.json` 的 `cold_read`。

## 2. 定级 [L0–L1 已验证；雕塑类 待验证]

| 级 | 内容 | 验收 |
|---|---|---|
| L0 占位 | 包围盒 + 接口 + 朝向 | 尺寸、位置、不穿相邻件 |
| L1 剪影体 | 外轮廓拟合成体 | 参考机位剪影 IoU + 轮廓残差 |
| L2 分块 | 大体块与主转折 | 各块剪影、主转折线回代 |
| L3 规律细节 | 排布、阵列、螺线、刻线、台地浮雕、面上安装件 | 同机位 + 逐件对照，参数可调、有种子 |
| L4 无规律细节 | 停：材质 / 法线 / 外部资产 / 手工（写 `route`） | — |
| skip | 不做（写 `skip_why`，如只作支承的人手） | — |

阶段 1 已初定级，这里按八问和歧义复核、改 ident.json 后重过闸。规则构件通常直接 L3；纹饰按分诊表（`levels.md` §5）；吻兽、兽面至少 L1–L2。一轮只升一级。标出**歧义点**（单视图下投影相近的几种结构、单视剪影的深度），这些出方案族（§3）。

## 3. 拟合：数形结合 [已验证]

**三类拟合对象，各有原理文档**：
| 对象 | 拟什么 | 原理 |
|---|---|---|
| 相机 / 对位 | 视角、距离、像面位置；绝对尺寸取先验 | `fitting.md` §1–§4 |
| 族参数 | 识别给出的结构里的少数量：起点、节距、宽度、端角、支承体轮廓 | `fitting.md` §5–§6 |
| 曲线 | 有性格的线：κ(s) 分段、等厚带、渐细笔触、拐点段 | `math-form.md` |

**每一层走同一个闭环**：
```
看 → 名 → 选（数学对象）→ 参（3–6 个可读参数）→ 认线 → 拟 → 顺 → 回代 →（不收敛回"认线"或"选"，或回识别）→ 取整写进 spec
```

**底线**：
- **先认线**：每条要拟合的线，先写"它对应模型里哪条曲线、参考视角下会怎么变形"。透视露出的底面 / 侧面边不是立面线。
- **结构不交给优化器**：优化器只调族参数；绝对尺寸在单视图下和距离不可分，取先验固定；参数撞边界 = 结构或标注有问题，不放宽边界。
- **几种数据互相打架 = 形不对**：剪影和特征点要求的相机不一致（一个对上另一个就掉），说明模型的形和参考不一致，回 §1 / §4b 查造型，不调权重掩盖（`fitting.md` §4）。
- **自己拟合为主，用户画线为辅**；自己多轮到收敛再交结果；只出同一来源的审美档。
- **单视图定不了结构，出方案族**，同视角同口径并排，由人定（`math-form.md` 3.7）。
- **测量够用就停**：精度目标 = 参考自身噪声底。

## 4. 构造 [已验证]

**顺序**：先做**一件**到位（必要时出同源 2–3 档，与参考局部并排），验收后再复制 / 实例化 / 装配。叠放的件**从被压的那件往上**逐件做，每件的位置按它压住的那件的实测外表面求。

**原理**（细节与公式见 `references/geometry-math.md`）：
- **截面先设计**：硬表面件绕支承的截面是折线（自有设计），顶点放在支承外扩 f 倍处，f 数值求到每条弦都不进支承；曲面件才用光滑截面。
- **同拓扑环放样**：截面在同一组参数上采样 → 相邻环连四边面 → 平面 n-gon 收口；布尔最后。同一放样件各站用同一 f 或相似截面，四边面才共面。
- **站点规则**：截面角范围随站变化的段加密；任何分段线性驱动量（外翻、收分、厚度）的转折处必须有站；站距 ≥ 2–3 倍倒角宽。
- **倒角**：活修改器，不 apply；面宽 ≥ 2 倍倒角宽（收拢段折线按比例压缩，不夹紧挤成窄条），台阶高 ≥ 2 倍倒角宽。
- **装配**：支承上的件，高程 / 法向取自真实几何（射线），不用公式外推；层间净距用射线实测、二分求抬高 / 倾角，件的所有子块都参与；随机实例的净距要计入随机量与曲率失配。
- **面上安装件**（铰座、凸台、铭牌、开关）：在安装位专设一个平折面，件平坐其上，落座高度按占地范围内支承面的实测最高点；长宽方向、窗 / 槽形状照参考局部定（`parts.face_frame` / `surface_seat` / `block`）。
- **对称在结构层，随机在单件层**；实例优先，晚实化；几何节点从构造逻辑出发写属性给材质（`gn-patterns.md`）。

**构造内自检**：每次改动后跑求值后审计 + 件间干涉审计（§6），不过就按 `pitfalls.md` 定位，改原理层面的原因，不打补丁。

## 4b. 逐件对照 + 同机位对比 ⇒ 检查点 B [实测]

1. **逐件对照**：每个有特征的件（铰座、凸台、端头、收口）出一张特写，和参考同部位放大图**并排**，核长宽比、朝向、窗槽形状、和邻件的关系。特写可以从同机位渲染里切（`ref_trace.py crop`），细小件另加近景机位。结论以"像 / 不像 / 缺失"开头。整体剪影对上了，单件造型仍可能是错的（护臂：铰座做成方盒切断叠板，参考是扁宽盒平坐在连续叠板上；用户截图才发现）。
2. **同机位对比**：拟合相机下渲染 RGB + alpha，三联图（参考 / 渲染 / 叠图轮廓）+ 剪影 IoU；IoU 及格线在看结果**之前**按口径定并写理由（`fitting.md` §0）。**IoU 只管外包络**：拉手、包角、抽屉分档这类剪影内部的差异它看不见，以逐件对照为准；`worst_cols / worst_rows` 用来定位细杆、出挑这类边缘差异。
3. **读差异**：先拿模型对照 ident.json 的节点表，再归类：
   - ident 有、模型里没有 → **遗漏**（回 §4 补做）；
   - 参数在、取值不对（等高该渐变、撇角为 0）→ **族参数**（回 §3）；
   - 生成器里根本没有这个自由度（腿不能撇、截面写死）→ **构造**（回 §4 加参数）；
   - ident 里就没有这件或认错了 → **识别**（回 §1）；
   - 整体平移 / 缩放 / 转角，逐件形状都对 → **相机**（只重拟相机）。
   一轮只改一层。

**检查点 B**：对比图、分件图（按构件类上色 + 图例）、关键件特写 + IoU 与审计数字 + 差异清单。`gate/accept.json` 过闸：先重查检查点 A；及格线有理由；每个 mount 节点都有逐件对照；每个判"不像 / 缺失"的件都在差异清单里，带归类和回到哪步；差异要么已修、要么用户接受（"待改"不过闸）；三项审计 pass。

## 5. 写实材质：按成因分层（Cycles）⇒ 检查点 C [已验证]

叠层顺序：底色（逐件色差）→ 大尺度斑驳 → 结构纹理 → 风化 → 缝脏（AO）→ 棱损（凸棱度）→ 粗糙度与凹凸（同一批噪波驱动）。检查三个尺度带（建筑：大 ≥ 30 cm、中 2–15 cm、小 ≤ 1 cm；小物体按构件尺寸等比换算）都有内容；"像塑料"几乎总是中尺度空白。起点 `scripts/layered_material.py`。评估用固定侧光、临时关用户合成（`materials.md`）。

## 6. 验收 [已验证]

1. **审计求值后的结果**（修改器 / GN 之后）：非流形、退化面、自交、法线（`eval_audit.py`）。原网格干净、求值后不干净 → 倒角 / 位移问题。
2. **件间与实例干涉**：`audit_instances.py`（`--objects` 对象两两；实例展开两两）。设计上嵌入 / 搭接的件不放进来；共面贴合也会报相交，按净距让开。
3. **冷启动构建**：全新进程从头构建一次（`cold_check.py` + `--factory-startup`）。
4. **同机位出图**：总览 + 每类构件特写 + 接口特写（`shot_rig.py`）。
5. **回执先读结论字段**：degraded / skipped ≠ 通过。
6. **出问题逐项关停定位**，不猜。

## 7. 交付 [已验证]

对象归位到前缀集合；清掉 `TMP_` / `QC_`；原点在接口中心、apply scale、法线朝外；存盘记 md5；外部格式先烘贴图、关单位盒归一化、导出后校验清单。

## 8. 沉淀：保持通用 [实测：2026-11-21 起执行]

| 层 | 放什么 | 位置 |
|---|---|---|
| 方法层 | 识别、拟合、回代、方案族、审计、出图、闸门 | skill `scripts/` |
| 几何原语层 | 支承、曲线网络、放样、折面板、叠层净距、面上排布、实例与对称群；领域无关的词命名，带合成 selftest | skill `scripts/`（如 `parts.py` `profilefit.py` `multiview.py` `bodies.py`） |
| 领域包 | 某类东西的规制与骨架（如中式屋面转角） | skill `scripts/`（`roofkit.py`） |
| 项目 | spec 数值、构件树、装配声明、这个物体的专用几何 | 项目目录 |

- **漂移警报**（出现任一条就停下做通用度检查）：项目生成脚本超过几百行且还在长；同一类修补第二次出现；从别的项目文件抄函数；修的是症状而不是原理。处理：原理写进 `geometry-math.md` / `pitfalls.md`；可复用的抽成原语；项目代码改为调用。
- 通用性用**非本领域的第二个案例**验证：只换项目层就能跑通才算通用。
- 每个案例结束写一页案例记录（`references/case-*.md`）：规则从哪次失败来、数字、用户口径。

## 9. 每轮循环与分工 [已验证]

反馈 → 判断落在哪步、哪层（§10）→ 改 spec / 识别 / 原理层的做法（不在生成脚本里改数）→ 快照 → 构建 → 审计 → 同机位 + 逐件对照，与上一轮、参考并排 → 回报：改了什么、三项证据、没做什么 → 通用度检查。
分工：人判断**好不好看**、定方向；agent 量测、生成、多轮自修、对比、出证据。

## 10. 回退信号：什么症状回到哪一步

| 症状 | 多半错在 | 回到 |
|---|---|---|
| 审计全过，但看着是另一种东西（软 / 硬不对、像脊椎像鱼鳍） | 面型、截面、拆件 | §1 八问 ⑦⑧、§1b |
| 剪影对上了，某个件和参考局部不像 | 单件造型（长宽比、朝向、平坐还是嵌入） | §4b 逐件对照 → §4 |
| IoU 过线，逐件却不像或缺件 | IoU 只看外包络，剪影内部的件（拉手、包角、分档）看不见 | 以逐件对照为准，按 §4b 第 3 步归类 |
| 剪影与特征点要求的相机打架（一个对上另一个就掉） | 模型的形和参考不一致 | §1 / §4b，不调权重 |
| 优化器把参数推到边界、或视角很怪 | 结构写错 / 标错点 / 尺寸与距离没固定 | §1、`fitting.md` §2–§3 |
| 去掉一组特征点后其余自洽 | 这组对应的结构写错 | §1，给它独立参数 |
| 改了先验（如支承体外形）IoU 明显下降 | 先验写死、没从参考拟合 | §3，支承体走拟合 |
| 拟合误差很小，用户说"不是这个风格" | 读错了线 | §3 认线 |
| 站上都净、站间穿进支承 | 站太稀 / 驱动量转折处没站 / 各站 f 不同 | §4 站点规则 |
| 原网格干净、求值后自交或退化 | 倒角宽 > 面宽 / 台阶 / 站距的一半 | §4 倒角 |
| 叠层件互穿 | 净距按厚度叠加；有子块没参与净距求解；随机量没计入 | §4 装配 |
