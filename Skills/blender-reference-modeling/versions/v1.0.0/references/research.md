# 知识边界：什么时候必须查资料，怎么查，怎么落地

本 skill 是**方法论**：判断顺序、闭环、判据、证据。它不是百科，也不是算法库。

- 每个新项目都会遇到这里没写的构造、材料、算法和 API。这时**自行联网查资料**，再按本 skill 的思路落地。
- 不要用记忆硬编，也不要因为 skill 里没写就跳过。
- 环境没有联网工具时，跟用户说明缺什么，请用户给资料，或明确标成"估计值"。

## 1. 什么时候必须查

| 类别 | 触发信号 | 例子 |
|---|---|---|
| **领域构造 / 规制** | 要定比例、构件名、搭接关系、做法顺序；或参考图里有看不懂的构件 | 古建：材分°、斗口模数、举折 / 举架、收分、侧脚、生起、瓦作 / 石作做法；其他风格（日式、徽派、哥特、和风神社）各有自己的规制 |
| **真实尺寸** | 参考图没有可靠比例尺，又需要一个绝对尺寸来标定 | 踏步高宽、门洞净高、瓦片规格、常见柱径 |
| **材料外观的物理量** | 定底色明度、粗糙度范围、金属度、次表面 | 石材 / 陶瓦 / 木材 / 漆的反照率（albedo）范围；风化、苔藓、锈的外观成因 |
| **算法** | 本 skill 的 `math-form.md` 第 6 节列为 [待验证] 的对象，或完全没列到的特征 | 有符号距离场浮雕、L-system / 空间殖民算法生成树、泊松盘采样、曲线拟合方法、网格重拓扑 |
| **软件 API / 版本差异** | 报错"找不到节点 / 输入名"；或换了 Blender 大版本 | Principled BSDF 输入在 4.x 改了名（如 `Coat Weight`、`Subsurface Weight`）；几何节点的节点名、输入名随版本变化 |
| **插件 / 工具用法** | 工具帮助不全，参数名和骨架不一致 | 先用工具自带的 help 或错误回执查参数，再查官方文档 |
| **用户提到你不熟的东西** | 风格名、作品名、术语 | 先查清是什么，再进入第 1 步"读图分类" |

## 2. 怎么查

1. **问题先写成一句话，带上要的数**。例："宋式厅堂举折，各缝举高相对前后橑檐方距离的比例是多少？"不要只搜一个词。
2. **一手来源优先**：
   - 规制类：原典或其权威注释本、学术论文、文物保护规范；
   - 物理量：测量数据库、论文；
   - API：官方手册、源码、发行说明；
   - 算法：原始论文或权威教材。

   二手来源（博客、问答）只用来定位一手来源，或给出可以立刻验证的做法。
3. **至少两个来源交叉**。数值不一致时记下范围，不要挑一个看着顺眼的。
4. **区分"规制"和"个例"**：规制给比例关系，个例（某座实物）给具体数。参考图属于哪种风格、哪个时代，就用哪套规制；不要混用宋式与清式。
5. **代码类结果**：只取思路和公式，自己用项目的 spec / curves 约定重写；外部代码不直接粘进构建脚本（许可证、依赖、版本都可能不对）。

## 3. 怎么落地（查到 ≠ 用对）

1. **数值进 spec，带出处**：`HIP_W = 300  # 来源：…（页 / 链接）；用户画线拟合 RMS 43 mm`。没有出处的数字，注明"估计"。
2. **规制只是起点**：规制比例 → 写进 spec → 同机位渲染与参考叠图 → 不合就以参考为准调整，并在 spec 注释里写明偏离了多少、为什么。参考图是目标，规制是先验。
3. **算法先做小样**：在空场景或无头进程里用最小输入跑通，出一张图、一个数字，再接进主构建。小样通过后，在 `math-form.md` 或项目文档里把它标成 [已验证]。
4. **API 查到就写进坑表**：版本差异、改名、默认值陷阱，记一行到 `pitfalls.md`（现象 → 根因 → 修法）。
5. **记录**：在工作日志里写查了什么、用了哪个来源、结论是什么。下一个 agent 不需要再查一遍。

## 4. 基于本 skill 发散补全

本 skill 给的是骨架，补全的方向是固定的：

| 骨架（不变） | 每个项目要补的（查 + 验证） |
|---|---|
| 读图分五类、写构件表 | 这种风格有哪些构件、叫什么、怎么搭 |
| 大形 → 中形 → 小形 | 这种风格的比例规制、大中小的典型占比 |
| 数形结合闭环（`math-form.md`） | 新特征适合的数学对象及其参数化 |
| 成因分层材质 | 这种材料的成因（怎么老、怎么脏、怎么坏）和物理量范围 |
| 几何节点按成因 | 这个环境的成因（气候、朝向、使用磨损） |
| 逐阶段证据与门 | 本环境有哪些工具、可信度如何（`toolchain.md` 的测法：给已知扰动，看能否抓到） |

补全时守住三条：
- **顺序不变**：大形不过不进中形。
- **证据不变**：每阶段要有图、数字、文件三项。
- **边界不变**：灯光、合成归用户，不覆盖用户的改动。

新做法跑通一个项目后，写回本 skill（标 [已验证]）；没跑通的只留在项目文档里。
